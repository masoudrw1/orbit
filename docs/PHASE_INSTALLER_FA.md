# فاز توسعه: نصب‌کننده و فعال‌سازی پنهان

این فاز روی همان نمونهٔ موجود ساخته شده است. خروجی، یک بستهٔ آزمایشی `.deb` است؛
هدف فعلی Pop!_OS 24.04 با COSMIC/Wayland و پردازندهٔ amd64 است.

## رفتار مورد انتظار

۱. بسته را نصب می‌کنی و Orbit به منوی برنامه‌ها اضافه می‌شود.
۲. Orbit را باز می‌کنی و در صورت تمایل گزینهٔ شروع پس از ورود را انتخاب می‌کنی.
۳. **Activate Hey Orbit** را می‌زنی. پس از آماده‌شدن موتور صوتی، برنامه پنهان می‌شود.
۴. می‌گویی **Hey Orbit** و مکث می‌کنی؛ جزیره باز می‌شود.
۵. نام یک برنامه یا روال را می‌گویی، یا در جزیره تایپ می‌کنی.
۶. با Escape یا دکمهٔ − دوباره پنهان می‌شود.

برای برگشت به تنظیمات، Orbit را از منوی برنامه‌ها باز کن. اجرای دوباره، همان نمونه را نشان می‌دهد.
**Deactivate Hey Orbit** شنیدن و شروع خودکار را غیرفعال می‌کند.
دکمهٔ × برنامه را همین حالا می‌بندد؛ فعال‌سازی ذخیره‌شده برای ورود بعدی حفظ می‌شود.

## نصب روی سیستم خودت

اول نمونهٔ قدیمی را ببند، سپس در پوشهٔ پروژه:

```bash
sudo apt install './dist/orbit-launcher_0.1.0~alpha2-1_amd64.deb'
```

مدل انگلیسی داخل بسته است؛ APT ممکن است برای نصب وابستگی‌های استاندارد سیستم به اینترنت نیاز داشته باشد.
ساخت بسته با نصب سیستمی آن فرق دارد. ابزار build نصب را انجام نمی‌دهد؛ دستور sudo بالا مرحلهٔ نصب است.

## چه چیزهایی برای یادگیری داریم؟

| فایل | مفهوم این فاز |
| --- | --- |
| `orbit/activation.py` | مدل تنظیمات، ذخیرهٔ اتمیک و شروع خودکار XDG |
| `orbit/ui.py` | چرخهٔ عمر برنامه، حالت پنهان و یک نمونهٔ فعال با D-Bus |
| `orbit/__main__.py` | گزینه‌های `--background` و `--quit` و مسیر مدل نصب‌شده |
| `packaging/orbit.desktop` | معرفی برنامه و آیکن به منوی لینوکس |
| `packaging/launch-orbit.sh` | اجرای برنامهٔ نصب‌شده مستقل از پوشهٔ سورس |
| `packaging/assets.json` | نسخه و هش ورودی‌های باینری بسته |
| `tools/build_deb.py` | چیدن فایل‌ها، تعریف وابستگی‌ها و ساخت `.deb` |

برای مطالعهٔ این فاز، از `Preferences` در `activation.py` شروع کن: دو مقدار boolean دارد،
یکی برای فعال‌بودن صدا و دیگری برای شروع بعد از ورود. این کلاس رابط GTK یا میکروفون را نمی‌شناسد.
بعد تابع `apply_preferences` را بخوان: تنظیمات و فایل شروع خودکار را هماهنگ ذخیره می‌کند.
تست `test_failed_settings_write_rolls_back_login_entry_and_settings` نشان می‌دهد چرا ذخیرهٔ قابل برگشت اهمیت دارد.

## روش ساخت و تست برای توسعه

```bash
python3 -m unittest discover -s tests -v
python3 tools/build_deb.py --fetch
```

`--fetch` اجازهٔ دانلود ورودی‌های ثابت بسته را می‌دهد. پس از پرشدن cache، همان build را بدون آن اجرا کن.
مدل، cache و `.deb` به Git اضافه نمی‌شوند؛ فایل‌های ساخت و کد تست به Git می‌روند.
بسته، `.venv` تو را کپی نمی‌کند. وابستگی‌های استاندارد Python و GTK را APT نصب می‌کند.

برای تست رابط بدون بازشدن میکروفون واقعی، یک D-Bus خصوصی مخصوص تست داریم:

```bash
GSETTINGS_BACKEND=memory GSK_RENDERER=cairo GTK_A11Y=none GIO_USE_VFS=local LD_LIBRARY_PATH="$PWD/.runtime/lib" GI_TYPELIB_PATH="$PWD/.runtime/lib/girepository-1.0" ORBIT_TEST_ISOLATED_BUS=1 dbus-run-session --config-file=tools/test-session-bus.conf -- .venv/bin/python tools/check_activation_ui.py
```

دو حالت دیگر همین helper، `--mode resume` و `--mode disabled` هستند.
این تست‌ها از جایگزین میکروفون و مسیر تنظیمات موقت استفاده می‌کنند؛ نتیجهٔ تشخیص صدای واقعی نیستند.
آزمون تشخیص گفتارِ بسته جداگانه با صدای مصنوعی و موتور واقعی انجام شده است.

۱. نصب واقعی و اجرای Orbit از منوی برنامه‌ها را امتحان کن.
۲. فعال کن و مطمئن شو پنهان می‌شود و با صدای خودت باز می‌شود.
۳. بازکردن دوباره از منو و Deactivate را امتحان کن.
۴. شروع خودکار را با خروج و ورود به حساب بررسی کن.
۵. نتیجه و خطاها را ثبت کنیم؛ سپس تغییرات همین فاز را مرور، commit و push می‌کنیم.

تغییرهای این فاز روی شاخهٔ `feat/installer-activation` هستند؛ ساخت فایل نصب به معنی push یا GitHub Release نیست.
رابط بومی GNOME همچنان یک فاز بعدی است؛ در GNOME روی Wayland از این مسیر Layer Shell نمی‌توان جزیره ساخت.
