# شروع Orbit، برای یک برنامه‌نویس جاوا

این پوشه، پایهٔ آموزشی پروژه است؛ هنوز نسخهٔ اول نهایی نیست.
نسخهٔ اول نهایی باید هم با صدا و هم با تایپ کار کند.
همهٔ کد را یک‌باره حفظ نکن. ابتدا محیط را بشناس، تست‌ها را اجرا کن و یک برنامه را باز کن.

## ۱. چهار مفهوم اولیه

| مفهوم | توضیح و معادل نزدیک در جاوا |
| --- | --- |
| Python interpreter | برنامه‌ای که کد پایتون را اجرا می‌کند؛ فعلاً چیزی شبیه نقش دستور `java` در اجرای برنامه در نظر بگیر |
| فایل `.py` | یک فایل کد پایتون؛ لازم نیست همهٔ کد داخل کلاس باشد |
| virtual environment یا `.venv` | محیط وابستگی‌های همین پروژه؛ JDK نیست و نسخهٔ مستقلی از سیستم‌عامل هم نیست |
| module / package | فایل قابل import / مجموعه‌ای از ماژول‌ها؛ پوشهٔ `orbit` پکیج پروژهٔ ماست |

`pip` ابزار نصب پکیج‌های پایتون است. `pyproject.toml` اطلاعات و وابستگی‌های پروژه را نگه می‌دارد؛ نقش‌هایی نزدیک به بخش‌هایی از `pom.xml` یا `build.gradle` دارد، اما معادل دقیق آن‌ها نیست.
GTK ابزار ساخت رابط گرافیکی است و PyGObject امکان استفاده از آن از داخل پایتون را می‌دهد.
Layer Shell هم برای جای‌گیری رابط روی دسکتاپ Wayland است؛ نصب GTK به‌تنهایی آن را فراهم نمی‌کند.

## ۲. اولین اجرای ساده

ترمینال را در پوشهٔ پروژه باز کن. پوشه‌ای درست است که `pyproject.toml` و `run.sh` در آن هستند.

```bash
python3 --version
python3 -m orbit --doctor
python3 -m unittest discover -s tests -v
```

دستور اول نسخهٔ پایتون را می‌گوید. `-m orbit` یعنی پکیج `orbit` را اجرا کن؛ نقطهٔ ورود آن `orbit/__main__.py` است.
`--doctor` فقط وضعیت نیازمندی‌ها را گزارش می‌کند. مقدار `false` الزاماً باگ نیست؛ می‌گوید یک نیازمندی هنوز حاضر نیست.
دستور سوم منطق برنامه را بدون نیاز به میکروفون یا رابط گرافیکی تست می‌کند.
اگر محیط مجازی را هنوز فعال نکرده‌ای، `python3` پکیج‌های پایتونِ سیستم را می‌بیند.
بعد از آماده‌شدن پروژه، `bash run.sh --doctor` محیط مجازی پروژه را انتخاب می‌کند و گزارش دقیق‌تری از نصب صوت می‌دهد.

اگر GTK روی سیستم حاضر باشد، اولین پنجره را از ترمینال معمولی دسکتاپ خودت باز کن:

```bash
bash run.sh --window
```

این حالت پنجرهٔ توسعه است؛ جزیرهٔ متصل به لبهٔ صفحه نیست.
نام یک برنامه را جست‌وجو کن و Enter بزن. برای خروج، دکمهٔ × را بزن.

## ۳. ساخت محیط پروژه

بسته‌های سیستمی را با APT نصب می‌کنیم و وابستگی‌های پایتون را داخل `.venv` می‌گذاریم:

```bash
sudo apt install python3-venv python3-pip python3-gi gir1.2-gtk-4.0 pulseaudio-utils
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -e '.[voice]'
```

`--system-site-packages` برای دسترسی این محیط به GTK/PyGObject نصب‌شده با APT است.
این تصمیم برای راحتی توسعه است؛ در بسته‌بندی نهایی دوباره بررسی می‌شود.
`-e` نصب editable است؛ با تغییر کد لازم نیست هر بار پروژه را دوباره نصب کنی.
`[voice]` وابستگی اختیاری تشخیص صدا را هم نصب می‌کند.
برای خروج از محیط مجازی: `deactivate`.
در ترمینال جدید برای برگشت به محیط: `source .venv/bin/activate`.

## ۴. اولین فرمان صوتی انگلیسی

```bash
python tools/download_model.py
bash run.sh --doctor
bash run.sh --window
```

دستور دانلود، مدل انگلیسی حدود ۴۰ مگابایتی را در `.models` می‌گذارد.
برای دانلود اولیه اینترنت لازم است؛ تشخیص بعدی محلی است.
در رابط، **Activate Hey Orbit** را بزن، منتظر آماده‌شدن و پنهان‌شدن برنامه بمان و بگو:

```text
Hey Orbit
[pause]
Open browser
```

عبارت `open browser` در صورتی ثبت می‌شود که یک برنامه با نام Firefox شناسایی شود.
برای برنامه‌های دیگر نام دقیق نمایش‌داده‌شده را امتحان کن.
اسم‌های تجاری نامعمول ممکن است خوب تشخیص داده نشوند. ابتدا روالی با نام ساده‌ای مثل `Programming` بساز.
این نمونه از Vosk برای تشخیص عبارت بیدارسازی و فرمان استفاده می‌کند؛ دقت محیط واقعی هنوز باید سنجیده شود.
پیش از اولین فعال‌سازی، میکروفون باز نمی‌شود. بعد از Activate، انتخابت ذخیره می‌شود و اجرای بعدی می‌تواند شنیدن را از سر بگیرد.
**Deactivate Hey Orbit** شنیدن و شروع خودکار را غیرفعال می‌کند. راهنمای کامل این تغییر در `PHASE_INSTALLER_FA.md` است.

## ۵. ساخت اولین روال

۱. دو برنامهٔ دلخواه را پیدا کن و کنار هرکدام + را بزن.
۲. بخش **Build your first routine** را باز کن.
۳. نام را `Programming` بگذار و در بخش alias بنویس `start coding`.
۴. **Save routine** را بزن.
۵. روال را با تایپ اجرا کن؛ اگر صدا فعال باشد، فهرست فرمان‌ها خودکار تازه می‌شود.
۶. بگو `Hey Orbit`، مکث کن و بگو `Programming`.

فعلاً روال فقط برنامه‌های دسکتاپ را باز می‌کند. بازکردن پروژهٔ مشخص در IDE و روشن‌کردن سرویس PostgreSQL در مراحل بعد اضافه می‌شوند.
درخواست اجراشدن یک برنامه به معنی آماده‌شدن کامل پنجرهٔ آن نیست.

## ۶. فعال‌کردن جزیرهٔ واقعی COSMIC

روی محیط فعلی، کتابخانهٔ native لازم در مخزن APT موجود نبود. ابتدا ابزارهای ساخت را نصب کن:

```bash
sudo apt install build-essential pkg-config meson ninja-build libgtk-4-dev libwayland-dev wayland-protocols gobject-introspection libgirepository1.0-dev
```

سپس:

```bash
bash tools/build_layer_shell.sh
bash run.sh
```

اسکریپت نسخهٔ ثابت upstream را از گیت‌هاب دانلود می‌کند و در `.runtime` همین پروژه می‌سازد؛
این مرحله اینترنت لازم دارد. اسکریپت ساخت خودش sudo نمی‌خواهد.
این اسکریپت تا قبل از نصب نیازمندی‌های ساخت و آزمون روی دستگاه، «نصب موفقِ تأییدشده» محسوب نمی‌شود.
اگر خطا رخ داد، همان خطا را بررسی می‌کنیم؛ نصب نصفه را با موفقیت اشتباه نمی‌گیریم.

در پوشهٔ اولیه‌ای که برای تو آماده شده، runtime محلی برای آزمایش COSMIC از بسته‌های رسمی Debian استخراج شده است.
این فایل‌های محلی وارد Git نمی‌شوند؛ منشأ و نسخه‌شان در `.runtime/PROVENANCE.json` ثبت شده است.
آزمون کوتاه جزیره روی همین دستگاه پاس شد. این روش، بستهٔ انتشار عمومی یا دستور نصب سیستم نیست.
برای checkout تازه، مسیر ساخت از سورس بالا راهنمای بازتولید است و هنوز اینجا اجرا نشده است.

## ۷. از کدام فایل یاد بگیرم؟

به ترتیب:

۱. `orbit/core.py`: تابع، کلاس، نوع داده و جست‌وجو.
۲. `tests/test_core.py`: ورودی و خروجی مورد انتظار.
۳. `orbit/config.py`: فایل JSON و ذخیرهٔ تنظیمات.
۴. `orbit/desktop.py`: ارتباط با برنامه‌های لینوکسی.
۵. `orbit/ui.py`: رویدادهای رابط گرافیکی.
۶. `orbit/voice.py`: دریافت صدا در thread جدا از رابط.

مثال سادهٔ پایتون:

```python
def greeting(name: str) -> str:
    return f"Hello, {name}"

print(greeting("Orbit"))
```

`def` تابع تعریف می‌کند، `:` شروع بدنه را مشخص می‌کند و فاصله‌گذاری بخشی از ساختار زبان است.
`str` و `-> str` راهنمای نوع هستند؛ مثل جاوا در همهٔ موارد بررسی زمان اجرا ایجاد نمی‌کنند.
`f"...{name}..."` رشته را با مقدار متغیر ترکیب می‌کند.

اولین تمرین واقعی: در `tests/test_core.py` یک alias تازه به مثال اضافه کن و تست کن که همان برنامه را پیدا می‌کند.
فعلاً برای اجرای کارها از کاتالوگ برنامه‌ها استفاده می‌کنیم؛ متن دلخواه را به shell نمی‌دهیم.

## ۸. اوبونتو و GNOME

Ubuntu توزیع است؛ GNOME دسکتاپ است. سازگاری با بسته‌های اوبونتو به‌تنهایی سازگاری جزیره را ثابت نمی‌کند.
هستهٔ فرمان و صدا جدا نوشته شده تا قابل استفادهٔ مجدد باشد.
GNOME روی Wayland مسیر Layer Shell ما را پشتیبانی نمی‌کند؛ برای جزیرهٔ بومی آن به یک رابط مناسب GNOME نیاز داریم.
حالت پنجره‌ای فعلاً یک fallback توسعه است، نه ادعای پشتیبانی کامل GNOME.
نقشهٔ راه در `ROADMAP.md` و راهنمای ریپوزیتوری در `GITHUB_FA.md` هستند.
